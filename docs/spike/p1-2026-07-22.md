# Tauri + Python Sidecar Spike Report

**Date:** 2026-07-22  
**Workspace:** `D:\agent`  
**Result:** **GO - P-1 accepted with one approved waiver and one N/A item**

Tauri 2 plus a Python sidecar is accepted for entry into P0. A Python 3.12 Nuitka standalone sidecar bundled in a current-user NSIS installer meets the 5-second startup target, passes cleanup/restart tests, and keeps Named Pipe latency far below 100 ms. The project owner approved a waiver for the untouched demo's `15.380s` development-only window startup because the installed product starts in `3.595s`. The Git commit checklist item is not applicable because this Windows spike workspace is intentionally not a Git repository.

## 7. Improvements Beyond The Manual Sample

1. Added a Windows Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`.
2. Added shutdown gating and a hard maximum of three crash restarts.
3. Fixed mutable child monitoring and killed unhealthy replacements.
4. Used exact listener/child PIDs instead of killing global `python*` processes.
5. Added real Rust Named Pipe coverage, response validation, warmup, failure counts, nearest-rank P95, and bounded pipe-busy retry.
6. Executed packaged `.exe` sidecars directly.
7. Added per-run nonce and PID identity checks to health and nonce checks to IPC.
8. Added HTTP read/write timeouts.
9. Made all metric scripts exit nonzero when their acceptance gate fails.
10. Automated forced kill, normal close, bounded restart, and evidence capture.
11. Configured and validated actual NSIS resources, install, upgrade, and uninstall.
12. Pinned Node, Rust, Python, Nuitka, PyInstaller, and transitive Python build dependencies.

## 8. Non-Blocking Follow-Up

1. Clean Windows 10 22H2 testing is still recommended, especially the WebView2-absent online/offline paths.
2. Tauri exe, sidecar exe, and installer need production certificate signing and timestamp validation before release.
3. Fixed port and pipe names remain. Nonce/PID validation prevents cross-instance confusion, but explicit single-instance policy, per-user pipe naming, and an explicit local-user ACL are still needed.
4. Synchronous Named Pipe read/write has no hard I/O timeout. Concurrent, malformed, oversized, disconnected, idle-client, and hanging-sidecar cases are not covered.
5. HTTP health and IPC readiness are separate threads; the monitor handles process exit, not a live process whose IPC thread has failed.
6. The sidecar is spawned before assignment to the Job Object, leaving a small parent-killed-during-spawn race.
7. The spike still uses `csp: null` and an unused opener permission; production capabilities need tightening.
8. Raw logs and JSON now exist, but no retained UI screenshots were captured.
9. Git commit/push is intentionally `N/A`: this Windows spike workspace is not a Git repository. The report, ADRs, evidence, installers, and hashes are the handoff artifacts.
