# P3.9 AppContainer 真机探针报告

**初始探针：** 2026-08-13  
**最终复跑：** 2026-08-14  
**机器：** Windows 11 `10.0.26200`，当前 PowerShell 为管理员会话  
**范围：** 验证当前 AppContainer 技术路线和生产 Factory，不执行 Git 写操作

## 1. 结论

AppContainer 路线在当前真机可行，并能与现有 `CreateRestrictedToken` 令牌叠加。

已观察到：

1. 当前 Windows 管理员会话可成功调用 `CreateAppContainerProfile`；标准用户会话仍需独立复跑。
2. `CreateProcessW` 配合
   `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES` 能启动 `cmd.exe` AppContainer。
3. `CreateProcessAsUserW` 配合当前主令牌能启动 AppContainer Python。
4. `CreateProcessAsUserW` 配合 restricted primary token 能启动 AppContainer `cmd.exe` 和本地 Python runtime，并执行完整边界探针。
5. 叠加后的子进程同时满足：
   - `TokenIsAppContainer = TRUE`
   - `IsTokenRestricted = TRUE`
   - 完整性 SID 为 `S-1-16-4096`（Low）
   - `TokenAppContainerSid` 与 Profile SID 完全相同
6. Workspace 加入包 SID 的可继承允许 ACE 后，子进程可以读写 Workspace。
7. 未给包 SID 授权的兄弟目录和用户 `NTUSER.DAT` 均被拒绝，Python 返回
   `errno=13`；对子进程直接调用 `CredReadW` 读取宿主临时凭据返回
   `WinError 5`。
8. 不授予任何 capability 时，current-token 和 restricted-token Python 的外部 TCP 返回
   `WSAEACCES / WinError 10013`；restricted-token `curl.exe` 返回连接失败 `7`。
9. 父进程能够访问本机回环探针，而 AppContainer 无 capability 时无法访问，
   说明回环失败不是服务未启动造成的。
10. 探针内置 19 项 acceptance check，最终 `passed=true`；临时凭据、Profile 和临时目录均清理成功。

因此，P3.9 的推荐底座为：

```text
restricted primary token
  + SECURITY_CAPABILITIES(AppContainer SID, zero capabilities)
  + Workspace 对包 SID 的精确 ACL
  + suspended launch -> Job Object -> token verification -> resume
```

空网络 allowlist 可由“零 capability AppContainer”落实为 OS 级默认拒绝。
非空 `host:port` allowlist 不能仅靠 AppContainer capability 精确表达，应继续
fail-closed，直到有 WFP/代理 broker 实现。

- 将可执行文件、Python runtime、标准库和依赖放在已授权的只读 runtime 根；
- 或显式把一个可信 runtime 根授予 AppContainer 包 SID `RX`；
- 不要默认授权整个用户 `AppData`、Python 安装父目录或源码仓库。

## 3. 可复用 Win32 ABI

### 3.1 Profile API

```c
HRESULT CreateAppContainerProfile(
  PCWSTR pszAppContainerName,
  PCWSTR pszDisplayName,
  PCWSTR pszDescription,
  PSID_AND_ATTRIBUTES pCapabilities,
  DWORD dwCapabilityCount,
  PSID *ppSidAppContainerSid
);

HRESULT DeriveAppContainerSidFromAppContainerName(
  PCWSTR pszAppContainerName,
  PSID *ppsidAppContainerSid
);

HRESULT DeleteAppContainerProfile(PCWSTR pszAppContainerName);
```

注意：

- 三个函数返回 `HRESULT`，不能按 `BOOL + GetLastError()` 处理。
- `Create`/`Derive` 返回的 SID 必须用 `FreeSid` 释放。
- Profile 名限制为 64 字符，并匹配 `[-_. A-Za-z0-9]+`。
- Profile 已存在时 `Create` 返回
  `HRESULT_FROM_WIN32(ERROR_ALREADY_EXISTS)`，此时再调用 `Derive`。

### 3.2 创建属性

```c
typedef struct _SECURITY_CAPABILITIES {
  PSID AppContainerSid;
  PSID_AND_ATTRIBUTES Capabilities;
  DWORD CapabilityCount;
  DWORD Reserved;
} SECURITY_CAPABILITIES;
```

空网络能力应设置：

```text
Capabilities = NULL
CapabilityCount = 0
Reserved = 0
```

属性键：

```text
PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES = 0x00020009
PROC_THREAD_ATTRIBUTE_HANDLE_LIST          = 0x00020002
```

属性列表数量应为 `2`，同时写入 security capabilities 与唯一允许继承的标准句柄。
创建标志至少包含：

```text
EXTENDED_STARTUPINFO_PRESENT | CREATE_UNICODE_ENVIRONMENT
```

生产实现还应保留 `CREATE_SUSPENDED`，以便在任何用户代码执行前加入 Job Object。

### 3.3 子令牌验证

创建成功、恢复主线程前必须验证：

```text
TokenIsAppContainer (29) == TRUE
TokenAppContainerSid (31) == 预期 Profile SID
TokenIntegrityLevel (25) == Low（S-1-16-4096）
IsTokenRestricted(token) == TRUE
```

任一检查失败都应终止子进程并 fail-closed。

## 4. ACL 要求

Workspace DACL 至少要给 AppContainer 包 SID 添加可继承 ACE：

```text
SID: S-1-15-2-...（该 Profile 的包 SID）
Flags: OBJECT_INHERIT_ACE | CONTAINER_INHERIT_ACE
Mask: FILE_GENERIC_READ | FILE_GENERIC_WRITE | FILE_GENERIC_EXECUTE | DELETE
```

生产实现建议：

1. 保留当前用户、SYSTEM、Administrators 的管理 ACE。
2. Workspace 使用包 SID 授予 `RWX`。
3. Runtime 根只给包 SID 授予 `RX`，不要给写权限。
4. ACL 修改前保存原始安全描述符，初始化失败或 broker 关闭时恢复。
5. 递归既有文件时，不能只修改顶层目录；必须确保旧文件也继承或获得包 SID ACE。
6. 不要把 `Restricted Code` SID 当作 AppContainer 包 SID，两者用途不同。

Low IL 本身还受 Mandatory Integrity Control 约束。如果实际目标目录带有禁止
Low IL 写入的强制标签，则除了 DACL，还需审查 SACL 的 Mandatory Label；不要
无条件降低系统目录或共享 runtime 的完整性标签。

## 5. 生产接入现状

以下项目已经完成：

1. isolation broker 管理唯一 AppContainer Profile 和 Package SID 生命周期。
2. Workspace 既有全树加入 Package SID `RWX/DELETE`，runtime 全树只加入 `RX`。
3. `process_sandbox` 的属性列表同时包含 handle allowlist 和 SECURITY_CAPABILITIES。
4. `CreateProcessAsUserW` 使用 broker 持有的 restricted primary token。
5. `CREATE_SUSPENDED` 后先加入 Job Object，再校验子令牌并恢复线程。
6. 空 egress allowlist 使用零 capabilities；非空 allowlist 在原生副作用前 fail-closed。
7. broker 关闭时释放 SID、删除自建 Profile、恢复 ACL、关闭 token 并清空 SecretHandle。
8. task-scoped Factory 已接入 `shell.execute` 和 `process.execute`。
