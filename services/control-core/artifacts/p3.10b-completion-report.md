### 3.2 原生 ConPTY 生命周期

主要文件：

- `packages/platform/windows/conpty.py`
- `packages/platform/windows/process_sandbox.py`
- `packages/platform/windows/isolation.py`

生产启动链：

```text
CreatePipe
-> CreatePseudoConsole
-> PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE
-> PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES
-> CreateProcessAsUserW(restricted primary token, CREATE_SUSPENDED)
-> AssignProcessToJobObject
-> 验证 restricted/AppContainer/Package SID
-> ResumeThread
```

关键实现：

1. 使用真实 `CreatePseudoConsole`，未使用 UUID 或说明文本模拟成功。
2. 显式设置 `STARTF_USESTDHANDLES`，并将三个标准句柄置空，防止
   `cmd.exe` 绕过 ConPTY 写入父控制台。
3. 只允许精确规范化的 `%SYSTEMROOT%\System32\cmd.exe` 或 workspace 内可执行文件。
4. 默认 shell 参数为 `/d /q /k`，ConPTY 流按 UTF-8 处理，不调用 `chcp`。
5. 支持 UTF-8 输入输出、resize、Ctrl-C、EOF、terminate、heartbeat、
   disconnect/attach 和断连宽限期回收。
6. 支持 timeout、输出上限、Job CPU/内存/PID 约束。
7. owner principal 和 workspace ID 只从服务端 `ExecutionContext` 派生，
   客户端不能覆盖。
8. 默认最多 8 个 active session、32 个 retained session。
9. 新增 pending-open 预留计数，防止并发 `open()` 越过 active-session 上限。
10. 成功、失败、timeout、output-limit 和 close 均关闭 ConPTY、原生句柄、
    Job、restricted token、AppContainer profile，并恢复 workspace ACL。
