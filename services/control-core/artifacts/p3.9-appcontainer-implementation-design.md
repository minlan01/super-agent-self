# P3.9 AppContainer 已实现设计

**初始设计：** 2026-08-13  
**实现复核：** 2026-08-14  
**目标：** 在现有 `WindowsProcessSandbox` 上叠加 AppContainer、restricted primary token 与 Job Object，形成 fail-closed 的 Windows 子进程隔离边界。  
**范围：** 本文记录当前生产实现、已验证约束和仍待人工验证的边界。

## 1. 当前结论

当前代码已修复 `ctypes.wintypes.LUID_AND_ATTRIBUTES` 不存在导致的初始化错误，并完成以下生产启动链：

```text
CreateProcessAsUserW(
  restricted primary token,
  CREATE_SUSPENDED,
  HANDLE_LIST,
  SECURITY_CAPABILITIES(AppContainer SID, zero capabilities)
)
-> AssignProcessToJobObject
-> 验证 primary/restricted/AppContainer/Package SID
-> ResumeThread
```

当前完整边界为：

```text
AppContainer（零 capability，系统级默认断网）
+ restricted primary token（去管理组和多余 privilege）
+ Package SID workspace ACL
+ Job Object（进程树和资源限制）
```

任一初始化、ACL、进程启动、Job 分配或令牌验证失败，都必须终止 suspended child，并禁止恢复线程。

当前真机探针已证明同一个 restricted AppContainer 子进程可以读写授权 workspace，并拒绝 workspace 外文件、用户 `NTUSER.DAT`、回环和公网访问。当前证据来自管理员 PowerShell；标准用户和第二账户仍待人工验收。

## 2. Broker 数据模型

### 2.1 `IsolationConfig`

当前实现：

```python
@dataclass(slots=True, frozen=True)
class IsolationConfig:
    workspace_root: str
    runtime_roots: tuple[str, ...] = ()
    deny_paths: tuple[str, ...] = ()
    env_whitelist: frozenset[str] = DEFAULT_ENV_WHITELIST
    egress_allowlist: tuple[str, ...] = ()
    enable_restricted_token: bool = True
    enable_appcontainer: bool = True
    enable_workspace_acl: bool = True
    enable_egress_filter: bool = True
    max_secret_lifetime_sec: int = 300
```

约束：

1. `workspace_root` 必须存在、是目录，并完成 `realpath`/`normcase` 规范化。
2. `runtime_roots` 必须存在、是目录，且不能与 `deny_paths` 重叠。
3. `runtime_roots` 不得指向用户配置根、完整源码仓库、完整 venv 或整个 `AppData`。
4. 任一非空 `egress_allowlist` 必须在原生副作用前 fail-closed，直到 WFP 或受控代理 broker 完成。
5. `enable_workspace_acl=True` 时必须同时启用 AppContainer；不能再用 `WinRestrictedCodeSid` 代替 Package SID。

### 2.2 `IsolationBoundary`

当前实现：

```python
@dataclass(slots=True)
class IsolationBoundary:
    config: IsolationConfig
    restricted_token_applied: bool = False
    appcontainer_applied: bool = False
    workspace_acl_applied: bool = False
    runtime_acl_applied: bool = False
    appcontainer_profile_name: str | None = None
    appcontainer_sid: str | None = None
    egress_rules: tuple[EgressRule, ...] = ()
    env_vars_blocked: int = 0
    secrets_issued: list[str] = field(default_factory=list)
    initialization_verified: bool = False
```

### 2.3 Broker 私有所有权

Broker 至少跟踪：

```python
self._restricted_token: Any | None
self._appcontainer_profile_name: str | None
self._appcontainer_sid_ptr: int
self._appcontainer_sid_text: str | None
self._profile_created_by_broker: bool
self._workspace_acl_snapshot: _AclSnapshot | None
self._workspace_acl_snapshots: dict[str, _AclSnapshot]
self._runtime_acl_snapshots: dict[str, _AclSnapshot]
self._active_launches: int
self._accepting_launches: bool
self._cleanup_pending: bool
self._closed: bool
self._state_lock: threading.RLock
```

Profile 名使用每个 broker 唯一的 ASCII 名称，例如：

```python
f"ZCode.P39.{uuid.uuid4().hex}"
```

Profile 名不得来源于任务输入。唯一名称避免并发 broker 共享 profile，减少 ownership 和删除竞争。

## 3. Win32 ABI

### 3.1 固定结构

```python
HRESULT = ctypes.c_long  # Windows 上固定 32 位

class SID_AND_ATTRIBUTES(ctypes.Structure):
    _fields_ = [
        ("Sid", wintypes.LPVOID),
        ("Attributes", wintypes.DWORD),
    ]

class SECURITY_CAPABILITIES(ctypes.Structure):
    _fields_ = [
        ("AppContainerSid", wintypes.LPVOID),
        ("Capabilities", ctypes.POINTER(SID_AND_ATTRIBUTES)),
        ("CapabilityCount", wintypes.DWORD),
        ("Reserved", wintypes.DWORD),
    ]

class TOKEN_APPCONTAINER_INFORMATION(ctypes.Structure):
    _fields_ = [("TokenAppContainer", wintypes.LPVOID)]
```

x64 下尺寸分别应为 `16`、`24`、`8` 字节。

关键常量：

```python
PROC_THREAD_ATTRIBUTE_HANDLE_LIST = 0x00020002
PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES = 0x00020009
TOKEN_QUERY = 0x0008
TokenType = 8
TokenIntegrityLevel = 25
TokenIsAppContainer = 29
TokenAppContainerSid = 31
TokenPrimary = 1
ERROR_INSUFFICIENT_BUFFER = 122
HRESULT_ALREADY_EXISTS = 0x800700B7
```

### 3.2 AppContainer Profile API

必须绑定：

```text
CreateAppContainerProfile
DeriveAppContainerSidFromAppContainerName
DeleteAppContainerProfile
ConvertSidToStringSidW
FreeSid
LocalFree
```

规则：

1. `CreateAppContainerProfile`、`Derive...`、`Delete...` 返回 HRESULT，按 `hr & 0xFFFFFFFF` 判断，不能读取 `GetLastError()`。
2. `Create` 返回 `0x800700B7` 时才调用 `Derive`。
3. `Create`/`Derive` 返回的 SID 用 `advapi32.FreeSid` 释放。
4. `ConvertSidToStringSidW` 返回的字符串缓冲区用 `LocalFree` 释放。
5. 只有 `_profile_created_by_broker=True` 的 broker 才删除 profile。
6. 删除失败不得丢失 ownership；保留 `_cleanup_pending=True`，下次 `close()` 重试。

## 4. 初始化与回滚

### 4.1 初始化顺序

```text
1. 验证配置、路径与非空 egress allowlist
2. 创建并验证 restricted primary token
3. 创建唯一 AppContainer profile，取得 Package SID
4. 保存 workspace 和 runtime roots 的原始安全描述符
5. workspace 加 Package SID RWX/DELETE ACE
6. runtime roots 加 Package SID RX ACE
7. 创建 workspace 内 temp 目录并继承 Package SID workspace ACE
8. 复读并验证所有 DACL
9. 标记 initialization_verified=True
```

重复调用 `initialize()` 时：

- 已成功初始化：返回同一 boundary，不得覆盖 ACL 快照或 profile ownership。
- 存在 `_cleanup_pending`：fail-closed，先完成清理。
- 已关闭且没有重新初始化契约：fail-closed，不隐式复用。

### 4.2 初始化失败回滚

回滚必须 best-effort 执行全部步骤，不能因前一步失败跳过后续步骤：

```text
1. 立即使 boundary 对新启动不可用
2. 恢复 runtime roots ACL
3. 恢复 workspace ACL
4. FreeSid
5. 删除本 broker 创建的 profile
6. 关闭 restricted token
```

应收集所有清理异常并在最终 `SandboxUnavailable` 中保留首个初始化错误与清理错误摘要。

### 4.3 正常关闭

正确生命周期：

```text
停止接收新 launch
-> kill/wait 所有 child
-> 关闭 Job 和进程/线程/管道句柄
-> 恢复 runtime/workspace ACL
-> FreeSid
-> 删除自建 profile
-> 关闭 restricted token
```

如果 `_active_launches > 0`，`close()` 必须拒绝清理或先由 owner 完成 `kill_tree()`；不能在子进程仍运行时恢复 ACL 或删除 profile。

## 5. ACL 策略

### 5.1 Workspace

宿主管理 ACE 保留当前用户、SYSTEM、Administrators。Package SID 只授予：

```python
FILE_GENERIC_READ
| FILE_GENERIC_WRITE
| FILE_GENERIC_EXECUTE
| DELETE
```

ACE flags：

```python
OBJECT_INHERIT_ACE | CONTAINER_INHERIT_ACE
```

不得给 Package SID `FILE_ALL_ACCESS`、`WRITE_DAC` 或 `WRITE_OWNER`。

### 5.2 Runtime roots

`runtime_roots` 只授予：

```python
FILE_GENERIC_READ | FILE_GENERIC_EXECUTE
```

不授予写入、删除、ACL 修改或 owner 修改权限。生产 runner 应使用以下之一：

1. 打包 sidecar/runner 目录；
2. 独立 Python embeddable runtime 及固定依赖目录；
3. 最小、只读、版本固定的 native runtime 根。

不要授权整个源码仓库、`.venv-win`、基础 Python 安装父目录或用户 `AppData`。本机探针已经证明宿主 venv launcher 在 AppContainer 中会因读取不到 `pyvenv.cfg` 而退出 `106`。

### 5.3 ACL 快照和验证

快照应保存：

```python
@dataclass(slots=True)
class AclSnapshot:
    path: str
    original_sddl: str
    was_protected: bool
```

验证接口不要只接收 SID 集合，应接收每个 SID 的最低 mask：

```python
required_aces: Mapping[str, int]
```

验证顶层 DACL 不足以证明旧文件已获得 ACE。若目录中可能已有文件，必须验证继承已传播，或在 broker 创建空 workspace/runtime staging 后再装载内容。

## 6. Process Sandbox 接入

### 6.1 启动上下文

增加统一 helper，避免 `create()` 和 `run()` 的校验漂移：

```python
@dataclass(slots=True, frozen=True)
class _IsolationLaunchContext:
    token_handle: int
    appcontainer_sid_ptr: int
    appcontainer_sid_text: str

def _isolation_launch_context(self) -> _IsolationLaunchContext:
    ...
```

该 helper 必须验证：

- boundary 存在且 `initialization_verified=True`；
- `restricted_token_applied=True`；
- `appcontainer_applied=True`；
- `workspace_acl_applied=True`；
- restricted token 与 Package SID 指针均非空；
- broker 正在接受 launch，且不存在 cleanup；
- broker 和 `SandboxProfile` 的 egress allowlist 均为空。

### 6.2 双属性列表

`InitializeProcThreadAttributeList` 的 attribute count 必须从 `1` 改为 `2`。写入：

```text
PROC_THREAD_ATTRIBUTE_HANDLE_LIST
PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES
```

安全能力结构：

```python
security_capabilities = SECURITY_CAPABILITIES(
    AppContainerSid=wintypes.LPVOID(appcontainer_sid_ptr),
    Capabilities=None,
    CapabilityCount=0,
    Reserved=0,
)
```

`handle_array` 和 `security_capabilities` 都必须保持 Python 强引用，直到 `CreateProcessAsUserW` 返回。第二个 `UpdateProcThreadAttribute` 失败时，必须删除属性列表并 fail-closed。

### 6.3 启动顺序

继续使用：

```text
CreateProcessAsUserW
+ restricted primary token
+ CREATE_SUSPENDED
+ EXTENDED_STARTUPINFO_PRESENT
+ CREATE_UNICODE_ENVIRONMENT
+ 显式环境块
+ stdin/stdout/stderr handle allowlist
```

之后严格按以下顺序：

```text
AssignProcessToJobObject
-> 验证 primary/restricted/AppContainer/Package SID
-> ResumeThread
```

错误信息应改为 `could not establish child isolation boundary`，不要把 SID 或 AppContainer 验证失败误报为 Job 分配失败。

## 7. 子令牌验证

pywin32 当前不导出 AppContainer token 信息常量，因此使用原生 `GetTokenInformation`。

恢复线程前必须验证：

1. `TokenType == TokenPrimary`；
2. `IsTokenRestricted(token) == TRUE`；
3. `TokenIsAppContainer == 1`；
4. `TokenAppContainerSid` 非空；
5. `EqualSid(actual, expected) == TRUE`；
6. 建议额外验证 integrity SID 为 `S-1-16-4096`（Low）。

`TokenAppContainerSid` 使用两次 `GetTokenInformation` 分配缓冲区，实际 SID 指针只在缓冲区存活期间比较。任一检查失败都必须：

```text
TerminateProcess/TerminateJobObject
-> wait
-> 关闭 process/thread/pipe handles
-> 清空 sandbox.pid
-> 禁止 ResumeThread
```

## 8. 环境与路径

AppContainer 启动时：

1. `TEMP` 和 `TMP` 强制覆盖为 `workspace_root\\.tmp`，不能继承宿主用户临时目录。
2. `cwd` 必须经 component-aware 校验位于 workspace 内。
3. executable 必须位于 workspace 或某个 `runtime_root` 内；不能仅检查绝对路径和文件存在。
4. 环境仍使用最小白名单，secret-like key 继续 fail-closed。

## 9. 生产装配

`WindowsPlatformAdapter.process_sandbox()` 不再把一个无 workspace 的全局 Job-only sandbox 宣称为可用能力。生产执行由 `WindowsProcessSandboxFactory` 在任务层创建 task-scoped 资源：

```text
task workspace
-> WindowsIsolationBroker(config)
-> initialize()
-> WindowsProcessSandbox(broker)
-> create/run/kill_tree
-> broker.close()
-> 删除 staged runtime
```

`shell.execute` 和 `process.execute` 已接入该 Factory。Factory 在 initialize、create、run、kill 或 close 任一步失败时都会尝试关闭 broker 并删除 staged runtime；对应生命周期测试已覆盖五类失败路径。

当前 Factory 真机探针返回 `rc=0` 和 `FACTORY_OK`。证据见 `artifacts/p39_factory_probe_console.txt`。

## 10. 测试矩阵

### 10.1 单元与 ABI

- 结构尺寸和字段布局。
- profile 创建、already-exists/derive、失败回滚。
- SID 字符串转换和不同 allocator 的释放函数。
- 属性列表 count=2，两个 attribute key 均写入。
- 第二个 attribute update 失败后删除 attribute list。
- 重复 initialize 不覆盖快照或 ownership。
- profile 删除失败后第二次 close 可重试。
- runtime roots 仅有 RX，workspace 有 RWX/DELETE。
- 非空 allowlist 在任何原生副作用前失败。

### 10.2 真机集成

- 子令牌同时为 primary、restricted、AppContainer，Package SID 相等。
- workspace 可读写。
- 未授权兄弟目录、Control DB、`NTUSER.DAT` 不可读。
- `TEMP`/`TMP` 位于 workspace 且可写。
- 零 capability 下互联网与 loopback 均被拒绝。
- 验证失败时 marker 文件不出现，证明 suspended child 未执行。
- timeout、cancel、memory、pids、output truncation 在 AppContainer 路径仍通过。
- broker close 后 profile 不残留，ACL 恢复，重复 close 幂等。
