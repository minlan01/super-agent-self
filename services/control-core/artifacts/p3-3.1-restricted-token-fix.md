# P3 3.1 受限令牌修复与手工验证

**日期：** 2026-08-12

## 故障原因

旧实现将 `LUID_AND_ATTRIBUTES` 和 `SID_AND_ATTRIBUTES` 当作
`ctypes.wintypes` 内置类型，但标准库没有这些结构体。此外，它在创建受限令牌后
立即关闭句柄，却把状态记录为“已应用”。现有测试又会捕获所有异常并退回
ACL-only，导致问题无法被测试发现。

## 本次修改

1. 使用项目已锁定的 pywin32 `CreateRestrictedToken` API，避免不完整的 ctypes 结构绑定。
2. 将管理员及管理员等价 SID 设为 deny-only。
3. 删除除 `SeChangeNotifyPrivilege` 外的令牌特权。
4. 使用当前有效身份和普通组构造 restricting SID 集合，使令牌产生真实的第二次访问检查。
5. 验证令牌是 restricted primary token 后，由 broker 持有原生句柄。
6. 增加幂等 `close()`，确保句柄释放。
7. 删除测试中的宽泛 ACL-only fallback，直接断言令牌属性。

## 手工修改步骤

若需要在另一份源码中手工复现本修复：

1. 打开 `packages/platform/windows/isolation.py`。
2. 删除 `_apply_restricted_token()` 中对
   `wintypes.LUID_AND_ATTRIBUTES`、`wintypes.SID_AND_ATTRIBUTES` 和
   `advapi32.CloseHandle` 的引用。
3. 使用 `win32security.OpenProcessToken` 获取当前主令牌。
4. 使用 `win32security.GetTokenInformation` 读取 `TokenUser` 和 `TokenGroups`。
5. 把管理员等价 SID 放入 `sids_to_disable`；把当前用户和有效普通组放入
   `sids_to_restrict`。
6. 调用：

```python
restricted = win32security.CreateRestrictedToken(
    source_token,
    DISABLE_MAX_PRIVILEGE | LUA_TOKEN,
    sids_to_disable,
    [],
    sids_to_restrict,
)
```

7. 使用 `IsTokenRestricted`、`TokenType`、`TokenPrivileges` 和 `TokenGroups`
   验证返回令牌。
8. 不要立即关闭成功创建的令牌；由 broker 持有，并在 `close()` 中释放。
9. 测试不得捕获任意异常后关闭受限令牌功能继续通过。

## 真机验证命令

在 `services/control-core` 下运行：

```powershell
.\.venv-win\Scripts\Activate.ps1

python -m pytest `
  packages/platform/windows/tests/test_isolation.py `
  -v --tb=short
```

然后执行 3.1：

```powershell
python -c "
from packages.platform.windows.isolation import create_default_isolation
import tempfile

ws = tempfile.mkdtemp(prefix='p3_verify_')
broker = create_default_isolation(
    ws,
    deny_paths=('C:\\Windows\\System32\\config',),
)
try:
    boundary = broker.initialize()
    print(f'隔离边界初始化: {boundary.initialization_verified}')
    print(f'受限令牌已创建并验证: {boundary.restricted_token_applied}')
    print(f'Workspace 配置探测: {boundary.workspace_acl_applied}')
    print(f'受限令牌句柄有效: {broker.restricted_token is not None}')
finally:
    broker.close()
"
```

预期四个字段均为 `True`，且没有异常堆栈。

## 安全边界说明

本次修复证明 broker 能创建、验证和持有受限主令牌。当前生产
`WindowsProcessSandbox` 仍通过普通 `subprocess.Popen` 启动子进程；在它改为使用
该令牌启动 runner 之前，不能宣称生产 runner 已受该令牌约束。

同样，当前 `_apply_workspace_acl()` 只验证目录可写与 deny-path 不重叠，并未实际
改写 Windows ACL；`check_egress()` 也只是策略判断，并未形成 OS 级网络隔离。这两项
仍应保持 NO-GO，不能由本次 3.1 输出替代。
